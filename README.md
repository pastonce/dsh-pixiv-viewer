# dsh-pixiv-viewer

DeepSeek Harness 的 Pixiv 看图插件：左侧栏入口、缩略图浏览、每日推荐、搜索 / 标签筛选、我的收藏、R18 开关、大图查看、保存与账号同步收藏。

## 功能

- 左侧菜单栏一键入口，进入独立的缩略图列表页
- 未搜索、未选分类时默认显示「每日推荐」（与 pixiv 官网 [discovery](https://www.pixiv.net/discovery) 发现页同源，随机打乱），可一键刷新；搜索框清空后同样回到每日推荐；每日推荐的「全部 / 全年龄」由 R18 开关直接控制（开 = 全部，关 = 全年龄），与官网发现页一致
- 底部栏左侧始终提示当前结果来源（如「「女の子」的搜索结果」「分类：原神」或「每日推荐」）
- 搜索划分为四类：标签 / 作品名 / 作者ID / PID（作品 ID）；类型下拉框与输入框、搜索按钮连成一体，操作提示内嵌在输入框占位文本中
- 搜索只在按回车或点击「搜索」时触发：切换类型、点选预设标签、输入过程都不会自动发起请求；切换热度档位、翻页会立即重新检索
- 搜索结果支持分页（上一页 / 下一页，每页最多 80 条 = 10 行 × 8 张，无丢页）
- 标签搜索支持集合运算：`|` 并集、`+` 或空格 交集、`-` 排除；运算符必须独立成词（前后各有一个空格），紧贴在词上的符号视为标签名的一部分（如 `R-18`、`C++` 不会被误判）
- 标签搜索预设区固定展示 399 个标签（三行横向滑动，399 = 3 的倍数、每列恰好 3 个）：其中 300 个从 posts > 20000 的热门标签中随机抽取，另 99 个来自「我的收藏」作品的标签（不足时从热门池补足）；排除热度档位类标签（如「原神1000users入り」）、按中文词义去重（「原神」与「Genshin Impact」只留一条）、按作品数从大到小排列；列表只在重新打开插件页面时刷新，每个标签悬停显示对应中文名；点击预设后标签末尾自动补空格、焦点回到输入框，便于继续输入运算符
- R18 相关标签受 R18 开关控制：开关关闭时，预设标签与输入联想中都不出现明确露骨标签（如 R-18、巨乳、中出し、全裸），收藏统计预设区同样过滤；打开开关后恢复显示（水着、内衣、ブルマ 等边缘标签不受影响）
- 输入联想自动匹配中文同义词（如「百合」→ yuri），联想列表每行右侧显示对应中文，支持 ↑/↓ 选择、空格 / 回车填入
- 内置 4.3 万条 pixiv 标签中文对照（数据来自 [ffdkj/Pixiv_Tag-Chinese-English-Translation-Table](https://github.com/ffdkj/Pixiv_Tag-Chinese-English-Translation-Table)，MIT，筛选 posts ≥ 1000，按热度排序）：查看器与收藏统计里的任意标签悬停可显示中文译名；输入框联想支持直接输入中文译名匹配到原标签（如输入「东方」→ 東方）
- 热度档位筛选：`100users入り` / `500users入り` / `1000users入り` / `3000users入り` / `5000users入り` / `10000users入り`，切换后立即按当前关键词 / 分类重新检索；标签 / 作品名 / 作者ID 搜索均支持
- 「最新 / 最旧 / 热门」排序，切换后立即按当前输入文本重新检索（每日推荐不受排序与档位影响，两个下拉框禁用）；在筛选结果内二次过滤（标题 / 标签 / 画师），筛选框可收起
- R18 开关（关闭 = 过滤掉 R18 作品；开启 = R18 与普通作品混合显示）、隐藏 AI 作品开关。两者划分原则与 pixiv 官网一致：R18 按 pixiv 官方的 `xRestrict` 分级标志（搜索结果、作者作品、每日推荐全部生效），AI 按上传者在 pixiv 上的「AI 生成作品」声明标签判定（AI生成 / AIイラスト / NovelAI 等，见下文「AI 判定说明」）；缩略图左下角的 R18 / AI 角标也按同一标准显示
- 预置分类：原神、崩坏：星穹铁道、绝区零、未定事件簿（支持分页与热度档位；选中分类后进行搜索仍在该分类内检索，标签 / 作品名类型有效）
- 自动过滤视频 / 动图（ugoira）作品
- 点击缩略图查看大图（左上角显示 PID、标题居中；多页作品翻页时先隐藏旧图再加载新页，键盘 ←/→ 或 A/D 翻页、Esc 关闭、加载失败可重试）
- 查看大图时滚轮以鼠标位置为中心放大（最高 8 倍）、放大后可按住拖动平移视角
- 查看器内可「复制图片」到剪贴板（在「保存图片」按钮左侧），也支持保存图片到本地
- 查看器左上角点击作者名（带作者 ID）→ 自动切到作者模式并检索该作者的全部作品，顶部提供「返回」按钮，完全还原刚才在浏览的界面（列表内容、分页、滚动位置与正在看的大图全部保持原样）；下方标签条显示全部标签，放不下时支持鼠标滚轮 / 横向拖动左右滚动
- 缩略图右下角悬停显示下载 / 复制按钮（下载自动取原图尺寸）；缩略图左下角显示 R18 / AI 角标，两者可同时出现
- 缩略图加载失败时可在该图上单独重试
- 收藏 / 取消收藏，与 pixiv 账号数据实时同步；收藏与取消收藏、下载、复制图片均有成功 / 失败提示，复制期间持续显示「正在复制图片」、下载期间持续显示「正在下载图片」，结束后弹出对应结果提示；多个提示竖向堆叠显示、互不遮挡
- 已收藏作品的缩略图右上角红色爱心常驻显示（未收藏时悬停才显示）
- 「我的收藏」：上方栏一键进入，分页拉取全部已收藏作品（底部栏显示加载进度），支持与普通搜索完全相同的检索与筛选——标签（含集合运算）/ 作品名 / 作者ID / PID 本地检索、热度档位、R18 / 隐藏 AI、最新 / 最旧 / 热门排序、分类词过滤、80 条每页分页，全部在本地内存完成、不产生额外 pixiv 请求；可直接在列表里取消收藏
- 「我的收藏」页的预设标签区变为收藏标签统计：统计所有收藏作品的标签频数，按数量从大到小排列（三行横向滑动），每个标签单元为「标签 × 频数」，悬停显示中文，点击仍进入搜索框
- 作者模式：右上角「作者」开关一键开启。开启后隐藏原神 / 星穹铁道 / 绝区零 / 未定事件簿四个分类，「全部」页改为展示 pixiv 推荐的作者卡片（作者名、用户 ID、头像、简介、作品数量、最近 3 张作品缩略图），右上角可一键刷新推荐；点击卡片按分页查看该作者的全部作品，作品视图顶部提供「返回」按钮回到作者列表与「加关注 / 已关注」按钮；「我的收藏」页在作者模式下变为已关注作者列表，形式相同，且此时在搜索框搜索任何内容（作者名 / 作者ID）都只在已关注的作者范围内检索
- 每张作者卡片带「加关注 / 已关注」按钮：加关注会直接用默认浏览器打开该作者的 pixiv 主页（pixiv 已对加关注强制启用 reCAPTCHA 人机验证，插件无法代为加关注），到网页端手动点击关注即可；取关即时生效并与 pixiv 账号实时同步，在已关注列表里取关后该卡片即时移除。作者卡片布局固定（简介恒占两行、缩略图恒占 3 个槽位），开关 R18 / 隐藏 AI 不会改变卡片高度
- 作者卡片缩略图左下角与作品列表一致地显示 R18 / AI 角标；关闭 R18 或开启隐藏 AI 时，被过滤掉的缩略图在空槽位上仍保留对应角标，一眼可知是被过滤而非加载失败
- 已注销作者：pixiv 的「共 N 位」计数会包含已注销账号，但接口不再返回其任何信息，插件会用统一的「已注销作者」占位卡片补齐列表末尾
- 搜索类型按模式切换：图片模式（默认）只显示「标签 / 作品名 / PID」三种，作者模式只显示「作者名 / 作者ID」两种；作者名搜索与官网 `/search/users` 同源（每页 10 位，卡片资料按需逐个懒加载，不挤占搜索请求）
- 作品数量按需逐个加载：只请求进入屏幕的卡片，且一次只排队一个请求（宿主端缓存 10 分钟），不会挤占搜索请求；卡片缩略图遵循 R18 / 隐藏 AI 开关
- 结果缓存：相同的搜索 / 分类 / 详情在 5 分钟内直接复用（收藏变更时自动失效），重复操作不再反复请求；图片走浏览器长缓存（7 天）；收藏列表按官方分页方式（48 条/页）逐页读取并缓存 5 分钟，重复进入立即命中

## 安装

```bash
dsh plugin add github:<你的用户名>/dsh-pixiv-viewer
```

本地目录安装：

```bash
dsh plugin add <插件目录绝对路径>
```

安装后需在 profile 的 `dsh.profile.bundles` 中确认 `dsh-pixiv-viewer` 已启用（`dsh plugin add` 会自动写入）。

## 登录（一次即可）

插件完全复用 pixiv 网页版接口，你只需粘贴一次浏览器里的会话 Cookie，不接触账号密码：

1. 浏览器中登录 https://www.pixiv.net/
2. 按 F12 → 「应用 / Application」标签 → 存储 → Cookie → https://www.pixiv.net → 复制 `PHPSESSID` 的值
3. 插件面板 → 「登录 pixiv」→ 粘贴 PHPSESSID → 「保存并登录」

插件会用这个 Cookie 验证登录并读取你的用户名；之后搜索、R18、热门排序、收藏同步全部走它。

Cookie 仅保存在本机 `~/.pixiv-viewer/`，不会被记录到日志。

> 注：PHPSESSID 与账号强相关，请勿泄露给他人。失效（登录状态过期）时在设置里重新粘贴即可。

## R18、排序与搜索说明

- **R18 开关**：关闭时只请求普通作品（过滤掉 R18）；开启时 R18 与普通作品混合显示。走网页版接口，登录后即可使用，未登录时打开开关会自动弹出登录提示。搜索结果、作者作品列表与每日推荐均按 pixiv 官方的 `xRestrict` 分级标志统一过滤，与官网「全年龄 / R18」划分一致。
- **排序**：「最新」与「最旧」均有效（作者作品列表同样支持）；「热门」与 pixiv 官网当前的搜索结果排序行为一致（pixiv 后端目前对 `popular_d` 返回与最新相同的顺序，官网「人気順」页也是如此；作者作品接口不返回收藏数，热门同样与官网作者页行为一致按最新排序）。「最受喜爱 / 最多浏览」没有对应的关键词搜索接口，故未提供；想浏览按人气排序的内容可用默认的「每日推荐」。切换排序会立即按当前输入框中的文本重新请求一次。
- **每日推荐**：使用 pixiv 的 `/ajax/discovery/artworks` 接口，与官网 [discovery](https://www.pixiv.net/discovery) 发现页同源，随机打乱后展示，点「刷新」重新抽取；「全部 / 全年龄」由 R18 开关直接控制（开 = 全部、关 = 全年龄）。每日推荐没有排序与档位概念，此时「最新 / 最旧 / 热门」与热度档位下拉框处于禁用状态。
- **AI 判定说明**：pixiv 的 AI 分类是上传者声明制——投稿时勾选「AI 生成作品」的作品会带上 AI 标签，官网搜索页的「AI 生成作品：非表示」过滤用的正是同一机制（服务端 `-AI生成` 排除，同样会漏掉只打了 AIイラスト 等标签而未声明 AI生成 的作品）。插件按同一原则过滤并打角标：隐藏 AI 开启时，服务端 `-AI生成` 排除 + 本地按 AI 声明标签集合（`AI`、`AI生成`、`AIイラスト`、`AIグラビア`、`生成AI`、`NovelAI`、`Stable Diffusion`、`Midjourney` 等）精确匹配兜底；角标显示同一套标准。列表接口里的 `aiType` 字段恒为 1、`sl` 字段是内容分级而非 AI 标记（手绘作品同样会出现 sl 2/4），两者都无法用作 AI 判定。显式搜索 AI 标签（如「AIイラスト」）时视为有意查看，不受隐藏 AI 开关过滤。
- **搜索类型**：
  - 标签：pixiv 标签部分匹配；支持集合运算（`|` 并集、`+` 或空格 交集、`-` 排除），可与热度档位组合（如 `女の子 空 - 雪` + `1000users入り`）；`|` `-` `+` 需前后各有一个空格独立成词才被识别为运算符，紧贴词尾的符号按标签名的一部分处理（如 `R-18`）
  - 作品名：按标题 / 说明文字搜索（`s_tc`）
  - PID：输入作品 ID，直接打开该作品
  - 作者名（仅作者模式）：按作者昵称搜索作者（与官网 `/search/users` 同源）；作者卡片资料（头像 / 简介 / 最近作品）按需懒加载
  - 作者ID（仅作者模式）：输入作者的用户 ID（数字）直接检索其全部作品，顶部横幅显示作者头像、昵称、ID 与「加关注 / 已关注」按钮（与点击卡片进入作者作品视图的效果一致）；查看器左上角点击作者名会自动切到作者模式并按 ID 检索
  - 图片模式（默认）下拉框只显示「标签 / 作品名 / PID」，作者模式只显示「作者名 / 作者ID」
- **作者模式**：数据来自 pixiv 官方「发现用户」（`/ajax/discovery/users`，与官网 [discovery/users](https://www.pixiv.net/discovery/users) 页面同源）、「关注用户」（`/ajax/user/{自己}/following`，与官网收藏页「用户」标签同源）与「用户搜索」（`/ajax/search/users`，与官网 [search/users](https://www.pixiv.net/search/users) 页面同源）接口；作者作品列表按官方网页自身的 48 条/批分批懒加载（80 条/页，最多读取最新的 480 条，支持最新 / 最旧排序，R18 与 AI 过滤与其他页面统一）；关闭作者模式时结果与输入框一并重置回每日推荐。「我的收藏」页处于作者模式时，搜索作者名 / 作者ID 只在已关注作者范围内检索（按官方关注列表接口逐页过滤，每页 48 条，不产生批量请求）。**粉丝数量**已从卡片上省略：pixiv 已将他人粉丝数设为隐私（历史可用的粉丝接口现在对非本人一律 403），接口中也不存在该字段。关注 / 取关复用网页版自身的 bookmark_add / rpc_group_setting 调用与 CSRF 令牌，未登录时自动提示登录；pixiv 已对「加关注」（bookmark_add.php）强制要求浏览器端 reCAPTCHA Enterprise 人机验证，程序化加关注一律返回 400，因此「加关注」按钮改为直接打开作者主页、由你在网页端手动关注（取消关注没有此限制，可正常使用）。已关注列表与作者搜索的「共 N 位」计数可能略大于实际卡片数：pixiv 会把已注销账号计入总数，插件会用统一的「已注销作者」占位卡片补齐缺失的槽位。
- **热度档位**：`xxxx users入り` 档位（如 `1000users入り`）按标签**包含**档位文本来筛选——pixiv 官方的 `1000users入り` 标签与同人里程碑标签（如「原神1000users入り」）都会命中；搜索结果本身带收藏数的场景（我的收藏）则直接按实际收藏数 ≥ 阈值过滤。档位筛选走普通标签搜索 + 本地标签检查，**零逐作品详情请求**，不会触发 pixiv 限流（搜索请求携带的标签列表是完整的）；隐藏 AI 按上文「AI 判定说明」的标签声明制过滤。档位标签由 pixiv 在作品收藏数过线时自动添加、其后不会移除，因此个别收藏数后来跌破阈值的作品仍会保留在档位里——与 pixiv 官方档位页的展示完全一致。
- **预置分类**：对分类下的每个关键词逐页取结果、按作品去重合并（如「崩坏：星穹铁道」同时搜中日文两个词）；选中分类后，标签 / 作品名搜索会把分类词作为交集条件附加进去，PID / 作者ID 搜索则自动退出分类。分类与简单标签搜索支持分页（每页 80 条）。
- **加载速度**：搜索结果（1 分钟）、作品详情（5 分钟）在宿主端缓存，重复操作直接命中缓存、不再经过 1.5s 限速器；图片走 pximg CDN 时不携带账号 Cookie，限速放宽（120ms 间隔、并发 ≤ 6），浏览器端缓存 7 天（由浏览器磁盘缓存管理），宿主端另有 48MB / 30 分钟的内存缓存（查看大图后立即下载 / 复制图片免二次拉取）；查看器按原始方式加载（大图从上到下渐进显示），并预加载多页作品的下一页与列表中下一张作品的首图。所有内存缓存都有硬上限（48MB / 固定条目数）与 TTL，且每 5 分钟主动清扫过期条目，不会无限堆积。

## 代理

国内网络环境需要代理。插件设置中配置代理地址（如 `http://127.0.0.1:7890`），留空则回退到 `HTTPS_PROXY` / `https_proxy` / `HTTP_PROXY` / `http_proxy` 环境变量。

## 账号安全说明

针对封号风险，插件内置了以下约束：

- 所有网页接口请求串行化，间隔 ≥ 1.5 秒；「我的收藏」按官方网页自身的分页方式逐页读取（48 条/页，5 分钟缓存），作者作品列表同样按 48 条/批分批懒加载（只按需取批，最多读取最新的 480 条），不做任何批量扫描
- 图片请求走 pximg CDN 且不携带账号 Cookie（仅 Referer + UA），独立限速（120ms 间隔、并发 ≤ 6）；重复内容由短 TTL 缓存与浏览器长缓存吸收，避免反复请求
- 只使用你自己的 `PHPSESSID` 会话，本地存储、绝不输出日志
- 收藏与关注写入复用网页版自身的 CSRF 令牌，仅在需要时刷新
- 不做 HTML 抓取、不做批量操作

尽管如此，插件并非 pixiv 官方客户端，任何第三方客户端的使用都存在账号风险，请自行斟酌。

## 开发

```bash
npm run check   # node --check 全部 lib 文件
```

结构：`lib/index.js`（宿主端，注入 HTTP 路由）、`lib/routes.js`（REST 接口）、`lib/pixiv.js`（pixiv API 客户端）、`lib/client.js`（浏览器端 UI）。

### 更新标签对照表

对照表数据每日更新，重新生成（需要 Node ≥ 22.13）：

```bash
# 先 clone / pull 数据仓库（含 16MB tag.sqlite）
git clone https://github.com/ffdkj/Pixiv_Tag-Chinese-English-Translation-Table.git pixiv-tag-table
# 生成并写入 lib/client.js（默认阈值 posts >= 1000；可改，如 3000 / 5000）
node scripts/build-extratags.mjs pixiv-tag-table/tag.sqlite 1000
```

也可直接把 URL 传给脚本（自动下载，走 `HTTPS_PROXY` 代理）。生成后运行 `npm run check` 并重启 DSH。
